## Required before production data

- Resolve whether legacy password accounts/sessions exist and define explicit, user-verifiable
  account linking; never auto-merge identities solely by email.
- Enforce verified email status during Clerk first-login provisioning or verify the Clerk policy
  and code path; current source does not inspect the email verification field.
- Set a production `CLERK_SECRET_KEY` for first-login profile provisioning and set issuer and
  authorized-party restrictions to actual production values.
- Redact/sanitize unexpected exception messages in server logs and validate trust-proxy behavior.
- Use TLS at the Railway edge, private DB networking, backups, a tested restore, and reviewed
  migration deployment.
- Never apply `apps/api/prisma/tmp_rebaseline_decision_vault.sql` to a production database.

Secret values were not printed, copied, or embedded in these documents.
